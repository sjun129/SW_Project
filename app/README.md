# 자취실록 앱 (Expo SDK 57)

세입자가 입주·거주·퇴거 시점의 방 상태를 위변조할 수 없는 기록으로 남기고, 임대인 확인과 퇴거 비교 리포트까지 이어 주는 앱입니다. 디자인은 Figma "v2 · 자유 탐색 구조" 섹션(`../design-refs/`)을 따릅니다.

## 실행

```bash
npm install
npx expo start
```

- **휴대폰**: 스토어의 Expo Go(SDK 57 지원 버전, 예: 57.0.9)로 터미널의 QR 코드를 찍습니다.
- **웹**: `npx expo start --web`으로 실행하거나, `npx expo export --platform web`으로 빌드한 뒤 `dist/`를 정적 서버로 엽니다.
- `.env.local`을 바꾼 뒤에는 `npx expo start --clear`로 다시 시작해야 값이 반영됩니다.

## 두 가지 모드

| | 데모 모드 | 서버 모드 |
|---|---|---|
| 들어가는 방법 | 로그인 화면의 "로그인 없이 둘러보기" | 이메일로 가입하거나 로그인 |
| 데이터 저장 | 메모리 (앱을 다시 켜면 초기화) | Supabase (DB와 Storage) |
| 거주 중 하자 신고 | 신고 입력과 최대 5장 사진 첨부 (메모리) | 신고와 첨부 사진 ID를 함께 저장 |
| AI 하자 태깅 | 구역별로 정해 둔 예시 결과 | OpenAI 모델 분석 |
| 임대인 응답 | 리포트 탭의 "임대인 화면으로 보기 (시연)" | 실제 웹 링크 `/c/<token>` |
| 실시간 알림 | 없음 | 임대인이 응답하면 앱 위쪽에 배너 |
| 계약서 사진으로 채우기 | 사용할 수 없음 (로그인 안내) | 사용 가능 |

서버 설정(`.env.local`)이 없으면 로그인 버튼이 꺼지고 데모 모드만 쓸 수 있습니다.

## Supabase 설정

1. Supabase 대시보드의 **SQL Editor**에서 `../supabase/migrations/`의 SQL 파일을 이름 순서대로 한 번씩 실행합니다. 모두 다시 실행해도 문제없게 작성되어 있습니다.

   | 파일 | 내용 |
   |---|---|
   | `20261020000000_init.sql` | 테이블 9개(leases, zones, inspections, photos, defects, confirmations, defect_reports, reports, payments), 소유자 전용 RLS, 해시 체인 트리거, 임대인 RPC, `originals` 버킷 |
   | `20261021000000_landlord_verify_events.sql` | 임대인용 사진 링크, 원본 검증 RPC(`verify_hash`), 알림·활동 `events` 테이블, 임대인 응답을 알림으로 남기는 트리거 |
   | `20261022000000_landlord_guard.sql` | 세입자가 자기 링크를 열면 열람으로 기록하지 않고, 세입자가 스스로 서명하는 것을 막음 |
   | `20261023000000_realtime_events.sql` | `events` 테이블을 Realtime에 등록 (실시간 알림 배너) |
   | `20261024000000_replace_photo_defects.sql` | 사진 하자 태그를 RLS 아래에서 원자적으로 교체하는 RPC |
   | `20261025000000_create_lease_rpc.sql` | 집·기본 구역·점검 단계를 생성하고 현재 집을 전환하는 원자적 RPC |
   | `20261026000000_defect_report_photos.sql` | 하자 신고에 같은 집의 거주 기록 사진을 최대 5장 연결 |

2. `.env.example`을 `.env.local`로 복사하고 프로젝트 URL과 **publishable(anon) 키**를 넣습니다. service_role 키는 절대 넣지 않습니다.
3. 개발 서버를 다시 시작합니다(`npx expo start --clear`).
4. 앱에서 이메일로 가입합니다. 프로젝트에서 이메일 인증을 켜 두었다면 메일의 링크를 누른 뒤 로그인합니다.
5. 비밀번호 재설정 메일의 링크가 앱으로 돌아오도록 대시보드 **Authentication → URL Configuration → Redirect URLs**에 `jachwisillok://reset-password`와 배포한 웹 주소의 `/reset-password` 경로를 추가합니다. Expo Go에서 테스트할 때는 `exp://.../--/reset-password` 형식의 개발 리다이렉트 주소도 허용 목록에 추가해야 합니다.

## AI 기능 설정

AI 하자 태깅과 계약서 읽기는 Edge Function `vision`이 OpenAI를 호출해서 처리합니다. 앱에는 OpenAI 키를 넣지 않습니다.

1. 함수를 배포합니다. 처음이면 `npx supabase login`을 먼저 실행합니다.

   ```bash
   npx supabase functions deploy vision --project-ref <project-ref>
   ```

2. 대시보드의 **Edge Functions → Secrets**에 아래 값을 넣습니다.
   - `OPENAI_API_KEY` (필수)
   - `OPENAI_MODEL` (선택. 기본값은 `gpt-6-astra`)

함수의 동작은 다음과 같습니다.

- 로그인한 사용자만 호출할 수 있습니다(JWT 검증).
- 하자 태깅(`task: 'defects'`): 호출한 사용자의 폴더(`<userId>/...`)에 있는 사진만 다룹니다. 호출한 사용자의 권한(RLS)으로 5분짜리 서명 URL을 만들어 모델에 넘깁니다. 결과는 라벨(곰팡이, 찢김, 스크래치, 얼룩, 파손, 들뜸, 누수 흔적), 0~1 비율로 표현한 위치, 확신도이고, 최대 8개까지 받습니다.
- 계약서 읽기(`task: 'lease'`): base64 이미지(JPEG, PNG, WebP, 약 4.5MB 이하)에서 주소, 계약 기간, 보증금, 임대인 전화번호를 읽습니다. 읽지 못한 값은 비워서 돌려줍니다.
- 결과는 JSON 스키마(`strict`)로 받기 때문에 형식이 어긋나지 않습니다.

함수를 배포하지 않았거나 호출에 실패해도 촬영 기록은 그대로 저장됩니다. 이때 태깅 화면에 "AI 분석을 쓸 수 없어서 하자를 표시하지 못했어요"라는 안내가 뜨고, 사용자가 직접 하자를 표시합니다. 하자를 임의로 채워 넣지는 않습니다.

## 위변조 방지 설계

- **촬영 경로 제한**: 앱 카메라로 찍은 사진만 기록합니다.
- **해시**: 촬영한 사진 바이트로 SHA-256 해시를 만듭니다(`expo-crypto`, `expo-file-system`의 `File`).
- **해시 체인**: 단계(입주, 거주 중, 퇴거)마다 `chain = sha256(이전 chain + 사진 해시)`로 이어 붙입니다. 시작값은 0이 64개인 문자열입니다. 서버 모드에서는 DB 트리거(`photos_before_insert`)가 서버 수신 시각과 체인을 계산하기 때문에 앱이 이 값을 조작할 수 없습니다.
- **수정·삭제 금지**: 사진 기록(`photos`)과 원본 버킷(`originals`)에는 수정, 삭제 정책을 두지 않았습니다.
- **소유자만 접근**: 모든 테이블은 RLS로 소유자만 읽고 씁니다. 임대인은 토큰으로만 접근하며, `security definer` RPC(`landlord_view`, `landlord_respond`)가 필요한 정보만 돌려줍니다.
- **AI는 보조 수단**: AI 결과는 참고용 표시이고, 원본 고정이 끝난 뒤에 실행합니다. AI가 실패해도 기록 자체에는 영향이 없습니다.

## 코드 구조

```
app/
├─ src/
│  ├─ app/            화면 라우트 (위 표 참고)
│  ├─ lib/
│  │  ├─ supabase.ts  Supabase 클라이언트, 인증 오류 한국어 변환
│  │  ├─ db.ts        서버 접근 함수 (스냅샷, 업로드, 확인 링크, 이벤트, AI 호출)
│  │  ├─ pdf.ts       HTML → PDF 저장과 공유
│  │  ├─ docs.ts      확인서, 리포트 HTML 템플릿
│  │  └─ reminder.ts  퇴거 알림 예약, 사용자 설정
│  ├─ store.tsx       앱 상태 (데모/서버 모드, 시드 데이터, 실시간 구독)
│  ├─ hash.ts         사진 바이트 읽기, SHA-256, 해시 체인
│  ├─ ui.tsx          공용 컴포넌트 (버튼, 칩, 카드, 헤더, 시트, 태그 사진)
│  ├─ toast.tsx       실시간 알림 배너
│  └─ theme.ts        색상 토큰과 폰트 (Figma 변수와 같은 값)
└─ assets/img/        로고, 마스코트, 샘플 사진, 구역별 예시 구도
../supabase/
├─ migrations/        DB 스키마 (위 Supabase 설정 참고)
└─ functions/vision/  AI Edge Function
```
